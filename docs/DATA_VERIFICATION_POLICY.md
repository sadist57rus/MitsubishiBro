# Политика проверки технических данных каталога

Дата ревизии политики: 2026-10-16.

## Правило публикации

Карточка модели не считается подтверждённой только потому, что в ней заполнены поля. У каждой записи есть `verificationStatus`:

- `unverified` — нет прямого первичного источника, привязанного к точному коду кузова, году/месяцу выпуска, рынку, двигателю и коробке.
- `partially-verified` — первичный источник подтверждает только перечисленные в примечании поля; остальные остаются ориентировочными.
- `verified` — все критичные сервисные поля в записи сверены с руководством/сервисной документацией для точной модификации. Статус нельзя выставлять по общим каталогам или форумам.

Наличие ссылки на общую страницу производителя не подтверждает конкретную цифру. Источник должен указывать на руководство или таблицу для конкретной модификации, а карточка должна фиксировать рынок, модельный год/период, код кузова, двигатель, трансмиссию, раздел/страницу и дату проверки.

## Иерархия источников

1. Руководство владельца, заводской сервис-мануал, бюллетень/каталог OEM для точного рынка и модификации.
2. Официальный региональный дистрибьютор/портал производителя.
3. Документация поставщика оригинального агрегата (только для конкретного агрегата).
4. Технические базы и независимые каталоги — только как вспомогательная перекрёстная проверка, не как единственное подтверждение критичных объёмов/допусков.
5. Форумы и пользовательские публикации — только как гипотеза для дальнейшей проверки, не как основание для метки «проверено».

- Toyota Japan manuals: https://manual.toyota.jp/ — руководства по модели/рынку; в разделе maintenance data могут быть спецификации жидкостей, объёмы, лампы и размеры.
- Toyota USA manuals: https://www.toyota.com/owners/warranty-owners-manuals/
- Mitsubishi Japan manuals: https://www.mitsubishi-motors.co.jp/afterservice/manual/
- Mitsubishi Europe manuals: https://www.ownersmanual.mitsubishi-motors-europe.com/
- Mitsubishi Russia manuals: https://www.mitsubishi-motors.ru/for-mitsubishi-owners/manuals/

Эти адреса являются стартовыми точками для поиска документов, а не подтверждением конкретной записи.

## Что проверять по каждой модификации

- Идентификация: код кузова/шасси, рынок, модельный год и месяц, двигатель, код коробки, привод, комплектация/тип фар.
- Жидкости: заводское обозначение и допуск, вязкость/класс, заправочный объём при обычной замене и полный сухой объём (если опубликованы), метод проверки уровня, температурные условия, необходимость замены фильтра/прокладки.
- OBD: стандартизованный код и общий смысл отдельно от OEM-подкода/блока; симптомы не объявлять доказательством неисправности конкретной детали.
- Лампы: тип цоколя/мощность отдельно для каждой фары и рынка; учитывать галоген, ксенон, LED и комплектацию.
- Неисправности: описывать как известные риски/симптомы, не обещать одинаковую частоту на всех годах; причина должна подтверждаться бюллетенем, сервисной документацией или несколькими независимыми источниками.
- Размеры, массы, расход топлива: фиксировать рынок, измерительный цикл и условия. Не объединять в одно значение разные кузова/приводы/двигатели.
- Отзывные кампании: проверять отдельно по рынку и VIN на официальном сайте производителя.

## OBD-II — безопасная трактовка

Общие коды P0xxx описывают направление диагностики, а не автоматически неисправную деталь. OEM-коды P1xxx и коды ABS/SRS/TCM/гибридных блоков могут требовать фирменного сканера. Перед заменой деталей нужно считать freeze-frame, текущие параметры и сопутствующие коды, затем выполнить процедуру проверки для конкретного автомобиля.

## Офлайн и авторские права

В приложение следует включать только собственные краткие справочные данные, ссылки/библиографию и документы, для которых разрешено локальное распространение. Нельзя скачивать и встраивать заводские PDF целиком без проверки лицензии/прав. Офлайн-карточка должна хранить дату и источник проверки; ссылка на источник может не открываться без интернета.

## Текущий статус каталога

На дату этой ревизии supplemental-модели имеют статус `unverified` и не содержат привязанных OEM-источников. Это намеренно: пока источник для точной версии не проверен, интерфейс не должен выдавать запись за заводскую спецификацию. Основные записи, существовавшие до этой ревизии, также не считаются подтверждёнными автоматически. Их необходимо проверять по тому же стандарту.
