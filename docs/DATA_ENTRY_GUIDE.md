# Руководство по внесению проверяемых данных

## 1. Привязка до поиска цифр

Сначала зафиксировать: марку/модель, код кузова/рамы, рынок продаж, модельный год и при необходимости месяц выпуска, двигатель, код КПП, привод (2WD/4WD), комплектацию и вариант оборудования (например, галоген/ксенон/LED). Если хотя бы один признак влияет на поле, а определить его нельзя, оставить поле `null` и объяснить причину в `limitations[]`.

Не считать название модели или общий диапазон годов достаточной привязкой. Не переносить значения между рынками, двигателями, коробками, приводами и поколениями.

## 2. Источники и поля

Каждый источник получает стабильный `id`, заголовок, URL, тип, дату доступа, область применимости и конкретный раздел/страницу/таблицу. Каждое значение содержит `value`, единицы измерения, условия/методику, `sourceIds[]` и статус поля. URL на общую стартовую страницу производителя сам по себе не доказывает цифру.

Приоритет: (1) руководство владельца/сервис-мануал/OEM-бюллетень для точной модификации; (2) официальный портал производителя или дистрибьютора; (3) документация производителя агрегата с VIN-привязкой; (4) независимые каталоги только для перекрёстной проверки; (5) форумы — только гипотеза, не доказательство. Не использовать пиратские копии, закрытые базы без лицензии или копировать таблицы руководств.

Критические значения (жидкости и объёмы, допуски ATF/CVT/МКПП, давление в шинах, моменты затяжки, тормозная жидкость, шины, ГРМ) требуют одного первичного руководства точной модификации или двух независимых источников. Иначе `partially-verified` максимум и `needsHumanReview: true`.

## 3. Статусы

- `unverified`: нет первичного источника, привязанного к точной модификации.
- `partially-verified`: подтверждены только перечисленные поля; остальные не подтверждены или оставлены `null`.
- `verified`: все критичные поля сверены с первичным руководством именно этой модификации; общие каталоги и форумы недостаточны.

Конфликт не разрешать выбором «более удобного» числа. Сохранить оба утверждения, их источники и область применимости, поставить `conflict: true`, `needsHumanReview: true`, а статус не повышать до разрешения.

## 4. Правила для null

`null` означает «не опубликовано/не найдено/не удалось подтвердить для точной модификации», а не ноль или отсутствие компонента. Причина должна быть указана в `limitations[]` с конкретным полем. Не подменять неизвестное приблизительным значением.

## 5. Предлагаемый формат пакета

Путь: `src/data/packs/<brand>/<model>-<chassis>.json`. Формат ниже — шаблон контракта для обсуждения; это ещё не интегрированная схема приложения.

```json
{
  "schemaVersion": 1,
  "modelId": "outlander-xl",
  "identity": {
    "make": "Mitsubishi",
    "model": "Outlander II",
    "chassisCode": "CW5W",
    "market": null,
    "modelYears": null,
    "engineCode": "4B12",
    "transmissionCode": null,
    "drivetrain": null,
    "trimOrEquipment": null
  },
  "sources": [
    {
      "id": "source-1",
      "title": "Название документа",
      "url": "https://...",
      "sourceType": "oem-manual",
      "accessedAt": "YYYY-MM-DD",
      "documentEdition": null,
      "sectionOrPage": null,
      "scope": "Точная применимость и ограничения"
    }
  ],
  "values": {
    "engineOilCapacityWithFilter": {
      "value": null,
      "unit": "L",
      "conditions": null,
      "verificationStatus": "unverified",
      "sourceIds": [],
      "conflict": false,
      "alternatives": []
    }
  },
  "verifiedAt": null,
  "limitations": [
    {
      "field": "engineOilCapacityWithFilter",
      "reason": "Первичный источник для точного рынка/модификации не найден."
    }
  ],
  "verificationStatus": "unverified",
  "needsHumanReview": true,
  "conflict": false
}
```

- Для каждого нового поля использовать тот же объект с `value: null`, если доказательств нет.
- `alternatives[]` хранит конфликтующие значения с отдельными ссылками и условиями; ничего не затирать.
- `verificationStatus` пакета не выше статуса наиболее слабого критического поля.
- Не включать выдуманный URL, страницу, дату или OEM-номер. Дата `accessedAt` ставится только после реального открытия источника.
- OEM-номер детали публиковать только при подтверждённой применимости по VIN/номеру рамы и официальному каталогу.

## 6. Перед PR

1. В описании перечислить точную модификацию и рынки, не охваченные пакетом.
2. Приложить таблицу URL / тип / какие поля подтверждает / раздел документа / дата доступа.
3. Перечислить все `null` с причиной, конфликты и поля для ручной проверки.
4. Обновить `docs/DATA_PROGRESS.md` и, после согласования архитектуры, покрытие модели.
5. Запустить `npm run check`, `npm run audit:catalog` и smoke-тесты. Один пакет модификации — один PR. Не сливать без проверки CI.
